# EAD7 リファクタリング指示書

## 目的

本プロジェクトは長年の機能追加により責務分離が不十分になっている。

目的は以下の3点であり、機能追加や仕様変更は行わないこと。

1. ヘッダ依存の整理
2. モジュール分離
3. 保守性向上

暗号処理やファイルフォーマットの挙動変更は禁止。

---

## 最重要ルール

### 禁止事項

以下は禁止。

* 暗号アルゴリズムの変更
* JSONフォーマットの変更
* ファイルフォーマットの変更
* 関数名変更による外部互換性破壊
* GUI挙動の変更
* エラーメッセージ内容の変更
* 例外仕様の変更
* CMake構成の大規模変更
* public API変更

### 許可事項

* ファイル分割
* namespace整理
* include整理
* forward declaration追加
* 実装ファイルへの移動
* 内部クラス追加
* private helper追加

---

## リファクタリング方針

### 1. master.h を解体する

master.h に多数の無関係な宣言が存在する。

以下のように責務ごとに分離すること。

例:

core/
crypto.h
crypto.cpp

kid/
kid.h
kid.cpp

kek/
kek.h
kek.cpp

mk/
mk.h
mk.cpp

ead7/
ead7.h
ead7.cpp

master.h は最終的に削除または最小限の集約ヘッダとする。

---

### 2. include依存を削減する

不要な include を削除する。

可能な箇所は forward declaration を使用する。

循環依存を解消する。

---

### 3. GUIとロジックを分離する

Qt GUIコードから暗号処理を直接実行しない。

GUI層

```
gui/
```

ライブラリ層

```
libead7/
```

へ責務分離する。

GUI層はライブラリを呼び出すだけにする。

---

### 4. JSON直操作を減らす

json型をアプリケーション全体へ露出させない。

可能であれば

```
struct KIDEntry
struct KEKEntry
struct MKEntry
```

などの型を導入する。

ただし既存のJSON構造は変更しない。

---

### 5. グローバル変数削減

不要なグローバル変数を削除する。

共有状態が必要な場合は Context クラスへ移行する。

---

## 実施手順

以下の順序で進めること。

1. include依存解析
2. master.h分割
3. モジュール分離
4. JSONラップ
5. グローバル変数整理
6. ビルド確認
7. テスト実施

各段階ごとにコミット可能な状態を維持すること。

---

## 成功条件

以下を全て満たすこと。

* ビルド成功
* 既存テスト成功
* 既存ファイルを読み込める
* 既存ファイルを書き出せる
* GUI動作が変わらない
* 暗号化結果が変更されない
* Git diff が主に構造変更であること

機能追加は不要。
仕様変更は不要。
目的は保守性向上のみ。
